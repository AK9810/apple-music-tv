## 计划中 / 正在探索

- **UI 重构（v2）** —— 全面重建表现层，以对齐 Apple 自己的 Apple Music 应用（首页 / 新内容 / 视频 / 电台 / 资料库）。这是最重要的工程 —— 设计分析与分阶段实施/迁移计划见下方 **[UI 重构](#ui-重构--对齐真正的-apple-music-应用)**。
- **真正的无电脑模式** —— 把剩余的代理路由移植到设备端 Kotlin，让浏览/资料库/搜索/歌词/封面在零电脑的情况下可用（播放已经做到了）。困难部分（bearer 抓取、webPlayback、Widevine）已经完成；剩下的是数据路由 + JSON 映射。
- **队列编辑** —— 用方向键在「接下来播放」中重排和移除（纯列表操作，不折腾解码器）。
- **歌词翻译** —— 在每行原文下显示 Apple 风格译文；先探测 Apple 的端点，否则用设备端 ML Kit 翻译。
- **自动播放 / 无限混音** —— 队列结束后以电台方式继续播放。
- **自动获取 MUT（登录代替复制粘贴）** —— 干掉手动「从 devtools 复制 token」这一步。两条路线，按现实程度排序：
  - **手机伴侣登录（首选）。** 现有的 `:8080` 手机页面增加一个「登录 Apple Music」按钮，在手机自己的浏览器 / WebView 中打开 `music.apple.com`。用户在那里登录后（2FA 在手机上很自然，不像在电视遥控器上那么痛苦），会话的 **`media-user-token`** 就存在于该站点的 cookie / `localStorage` 中 —— 读取它并自动 POST 到电视。这命中的正是目前手动粘贴所用的同一个端点；我们只是替用户把输入框填好。现有的 QR / 8080 配对就是骨架 —— 这把「粘贴」换成了「提取」。
  - **电视内 WebView 登录。** 一个指向 `music.apple.com` 的应用内 `WebView`；认证后取出同样的 `media-user-token`。UX 最干净（永远不用离开沙发），但风险更高：用方向键输入 Apple ID + 2FA 很痛苦，而且 Apple 可能封禁内嵌 / WebView 登录或弹出验证码。
  - **可行性 / 注意事项。** 没有官方的 token API —— 两条路线都是读取 Web 播放器在一次真实登录后自己存储的 token，所以这是抓取我们自己的已认证会话，而不是 Apple 的服务器。需要留意：2FA、验证码，以及登录流程 HTML 变化（与 bearer 抓取同样脆弱）。bearer + storefront 检测已经在服务端实现，所以新增的只有 MUT 的交接。先做手机路线；把电视内 WebView 当作可选延伸。
  - **提取究竟必须怎么做（约束）。** 你无法从普通的外部浏览器标签页中读出 token —— 会话存在于*它自己*的源（origin）中，而不是我们的。所以要么：(a) 用户在**我们控制的嵌入式 WebView / iframe** 中完成认证（手机伴侣或电视端），登录后我们可以从该 WebView 的 cookie / `localStorage` 中读取 `media-user-token`；要么 (b) **服务器参与认证握手**（代理 `music.apple.com`），在 Apple 返回会话 token 的响应处拦截。两者都意味着*我们托管登录入口* —— 一个单纯的「在你的浏览器中打开 Apple」链接无法把 token 交回来。这是下次真正需要做的设计决策。

## UI 重构 —— 对齐真正的 Apple Music 应用

目标是 Apple 自己的 Apple Music 应用（首页 / 新内容 / 视频 / 电台 / 资料库 / 正在播放的布局）。这是一次**仅限表现层的重建** —— 数据层、ViewModel、代理路由和独立播放路径完全保持不变；每个屏幕都已经由一个 ViewModel 提供数据，所以我们更换的是*外观*，而不是加载方式。按屏幕逐步发布，放在开关后面，让新旧界面共存，每一步都可回退。

### 究竟是什么让 Apple 的 UI 看起来像 Apple

从真机应用中研究得出。这个观感不是单一元素 —— 而是约 8 套被一致使用的系统：

1. **材质与层次。** 半透明、模糊的表面（导航胶囊、卡片、简介/元数据框）叠在一层柔和的、由内容衍生的**氛围背景**之上（从当前封面/栏目提取的、压低饱和度的渐变，而不是纯黑）。一切都像是浮在那层背景上的玻璃。
2. **一套卡片系统，处处使用。** 约 14 的圆角，卡片**自身**的宽高比（绝不加黑边），封面*上方*一个全大写微标签，标题 + 灰色副标题在*下方或内部*。聚焦 = 放大 ~1.06 + 提亮 + 白色标题；未聚焦则更暗。每个栏目都是同一种卡片。
3. **字体层级。** SF 风格。极小的全大写、宽字距标签（"UPDATED PLAYLIST"），粗体标题，中灰副标题，宽裕的行高。只有三四种字号，反复复用 —— 而非随手指定。
4. **更丰富的顶部导航。** 首页 · 新内容 · 视频 · 电台 · 资料库 · 正在播放，外加搜索图标和**设置**（齿轮）图标，放在一个半透明胶囊中。（我们目前是 立即聆听 / 浏览 / 资料库 / 搜索 / 正在播放。）
5. **栏目语法。** 带标题和「查看全部」的横向栏目；卡片下方带副标题。歌曲渲染成**三列的行网格**（封面 + 标题 + 艺人），而不是单一列表。大型**焦点主推**（两张宽卡片并排）引领页面。
6. **详情布局。** 专辑/播放列表 = **双栏**（左侧大封面；标题、编辑引言 + MORE、播放/随机/+/···，右侧编号曲目列表）。艺人 = **全出血主视觉**图片，播放按钮与名字叠加其上，主视觉上有「热门歌曲」网格，一个半透明的**简介框**带 FROM / BORN / GENRE 元数据，以及一排圆形头像的**相似艺人**。
7. **视频。** 暂停的静帧上叠一个预览**浮层卡片**（缩略图 + 标题 + 艺人 + 时长 + HD + "From Beginning"），然后是完整播放器：左下角标题/艺人、进度条、信息、···、列表。
8. **动效。** 进入详情时的共享元素过渡、主视觉封面的轻微视差、聚焦时的弹簧动画。

### 阶段 0 —— 设计系统基础（暂无可见变化）

先建好套件，让后续每次屏幕替换都便宜且一致：

- **Token** —— 单一的 `Tokens`/`AmTheme` 对象：颜色角色（surface、surfaceGlass、textPrimary、textSecondary、labelUppercase、强调色 `#FA233B`）、圆角、间距刻度、高度（elevation）以及字体层级。
- **氛围背景** —— 复用 `rememberArtworkPalette` 在整个外壳后面驱动一层低成本的渐变洗色（单次绘制，Fire TV 上不使用模糊）。
- **核心组件** —— `AmCard`、`Shelf`、`SectionHeader`、`SongGridRow`（三列）、`HeroSpotlight`、`TwoPaneDetail`、`ArtistHero`、`MetadataBox`、`CircleAvatar`、`PillNav`、`GlassSurface`（半透明遮罩；仅在 `Build.VERSION >= 31` 时使用真实模糊，否则回退到着色遮罩）。

### 阶段 1 → 6 —— 迁移（逐屏进行，放在 `Dev → New UI` 开关后）

1. **基础** —— 落地 token + 组件库；暂不接入任何屏幕。
2. **卡片与栏目** —— 把首页 + 浏览改为使用 `AmCard`/`Shelf`；加入三列歌曲网格；统一聚焦状态。视觉收益最高，风险最低。
3. **导航** —— 重命名并扩展顶部导航：**立即聆听 → 首页、浏览 → 新内容**，加入**视频**和**电台**标签（接入已有的音乐视频分组 + 电台/站点端点），保留资料库 / 正在播放，加上搜索和设置图标。更新返回行为 + 目前仍写着「立即聆听」的退出对话框文案。
4. **详情页** —— 双栏专辑/播放列表；艺人全出血主视觉 + 热门歌曲网格 + 简介框 + 相似艺人圆形头像。
5. **正在播放 + 视频** —— 让播放器界面元素对齐 Apple 风格；加入视频预览浮层卡片和完整播放器控件。
6. **动效** —— 共享元素/视差/聚焦弹簧；处处使用氛围洗色。

### 护栏（不要回退 Fire TV 性能 —— 来之不易）

- **API 31 以下禁用 `Modifier.blur`**（在 Fire TV 上是空操作 / 很慢）—— 改用着色半透明遮罩。
- 保持绘制调用预算低、使用 RGB_565 位图、共享 Coil 加载器、不进行多通道合成（与 `DynamicBackground` 和动态卡片防抖相同的教训）。
- 仅限表现层：**不要**改动数据源、ViewModel 或独立播放路径。
- 每个 PR 只改一个屏幕，让每一步都可审查、可回退；开关让两套 UI 可以同时发布。

## 已知问题

- **立即聆听 / 浏览中垂直焦点不均匀** —— 焦点移动时列表会滚动，行落点略微偏离中心；LazyColumn 不应在聚焦时重新锚定。
- **电台节目**（非直播的单集）在播放接通前是隐藏的；Apple Music Radio 直播可以正常工作。
- **音量均衡**为实验性功能，默认关闭。
