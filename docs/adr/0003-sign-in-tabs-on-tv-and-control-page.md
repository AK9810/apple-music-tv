# 登录交接的界面结构：电视三页签、控制台页四页签

**状态**: accepted（2026-11-14）

## 背景

到 2026-11 为止，把 MUT 交给电视有三条并列的**录入方式**（见 [GLOSSARY.md](../../GLOSSARY.md)）：控制台页粘贴、companion、iOS 快捷指令。但它们的界面入口失衡：

- 电视**引导页**的登录步骤把三种方式挤在一屏：左侧一大段说明、右侧两个 150dp 二维码，总高约 438dp，而 1080p 下内容区只有约 384dp —— 底部被 `clipToBounds` 直接截掉（实测截图确认）。同时这里没有任何一处能完整读完第一条方式。
- **控制台页**（`:8080`）是唯一把三种方式都写全的地方，却是一页从上到下的 13 张卡片、纯英文。手机上要先滑过半页设置项才看得到粘贴框；iOS 用户还要靠 UA 判断整页换文案，没有"我想看另一种方式"的入口。

## 决策

把"选择哪种录入方式"提升为两端的**一等界面结构**，两端各用页签承载：

1. **电视引导页的登录步骤改成三页签**，一页签一方式：`浏览器粘贴` / `伴侣 App` / `iOS · iPadOS`。每页一个 160dp 二维码 + 一句话摘要 + 可手输地址；完整步骤留在控制台页，电视不再承担长文。页签用仓库既有的 `Surface` 药丸样式（与 `TopNavBar` 一致），焦点到达即切换。
2. **控制台页改成四页签的纯 CSS 单页**：`登录` / `Android 伴侣 App` / `iOS 快捷指令` / `设置与诊断`。用隐藏 radio + `:checked` 控制面板显示，不刷新、日志轮询不中断；`?tab=` 只用于指定默认页签与深链。现有 13 张卡片里，设置与日志全部移入第 4 页签。
3. **默认页签跟随访问者**：iOS UA → 第 3 页，Android UA → 第 2 页，桌面与 companion WebView → 第 1 页。页签本身始终可见，用户可自行切换；`?ios=1` 与 iPad 桌面模式的跳转逻辑保留，只是改为落到第 3 页。
4. **控制台页双语（简体 / 英文）**：`?lang=zh|en` 优先，否则看 `Accept-Language` 首个语言的主标签，默认英文；右上角一个切换链接，不带 cookie。页面文案由 Kotlin 侧两份 `PageStrings` 提供，服务端渲染，缺一条翻译即编译失败。
5. **粘贴成功的落点统一**：`GET/POST /set-token` 都 303 到 `/?tab=1&saved=1`，第 1 页签顶部显示绿色成功横幅；删除只服务 `GET /set-token` 的 `tokenReceivedPage()`。
6. **桌面浏览器才渲染二维码**：`Other` 且 UA 不像手机时，第 2/3 页签各渲染一个服务端生成的 SVG 二维码（companion APK、`/?ios=1`）；手机与平板分支不渲染 —— 它们自己就在目标设备上。
7. 交付拆两个 PR（控制台页、电视引导页），各自独立可验收；本 ADR 与 `docs/ios-shortcut*.md` 随控制台页那个 PR 走。

## 考虑过的替代方案

- **保留一屏、缩小字号/二维码硬塞**：1080p 下缺约 50dp，缩到能放下就意味着二维码小于 120dp、说明小于 11sp，扫码与 10-foot 可读性同时受损，放弃。
- **服务端四套 `?tab=` 路由**：每次切换整页重载，日志面板与滚动位置重置，且增加四条路由的状态面；这页没有必须服务端分页的内容，放弃。
- **cookie 记住语言**：`send()` 不支持 `Set-Cookie`，为一行偏好加响应头能力不划算；`?lang=` 可收藏、可分享，够用，放弃。
- **电视把自身语言塞进二维码 URL（`?lang=zh`）**：多 8 字节容量没问题，但会把"需要手输的地址"变长，而中文用户的手机 `Accept-Language` 本来就是中文，放弃。
- **电视继续显示完整步骤**：与网页重复两份长文，且必然漂移；电视只留一句话 + 指向网页，长文只有一份，放弃。

## 后果

- 控制台页的 HTML 变长（四个面板与两份文案都在一个响应里），局域网内可忽略；但**新增任何页面文案都必须同时补中英两份**，否则编译失败——这是有意的约束。
- 电视与网页的文案分工固定下来：电视一句话、网页长文。以后改步骤只改网页，电视只在"方式本身变化"时改。
- 页签与默认页签的选择依赖 UA 判断，`PageAudience` 的优先级（companion 标记 > `ios=1` > iPhone/iPad > 其它）因此成为协议的一部分，已有单测锁定。
- 成功横幅取代了原来的独立落地页：companion 的 WebView 会落到控制台页而不是一句"Token received"，自动化脚本不受影响（它们只看 `GET /status`）。
- 范围外：companion APK 自身界面不中文化；`?lang` 不影响电视界面语言；Shortcut 的 v1.7 钉版与签名不变。
