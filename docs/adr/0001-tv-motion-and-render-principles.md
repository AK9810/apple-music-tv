# TV 动效与渲染性能原则

**状态**: accepted（2026-10-31）

## 背景

基线设备雷鸟 FF 55R69A（四核 Cortex-A73 / 3GB / 约 60Hz）上，D-pad 焦点移动、Now Playing 打开与切歌、页面转场、列表滚动存在**渲染型卡顿**（掉帧 / 动画帧率不足），与内存无关。代码审计确认三个直接元凶：

1. tv-material 1.0.0 的卡片 `glow` 用 `Paint.setShadowLayer` 绘制**真模糊阴影**（本项目用 18–22dp 半径），每张获得焦点的卡片每帧都在做一次模糊；
2. `AppShell` 的 `NavHost` 未配置转场，使用 navigation-compose 2.8.1 默认的 **700ms 全屏淡入淡出**——每次导航都有两块全屏内容同时合成约 42 帧；
3. Now Playing 封面是**双层 crossfade**（Compose `Crossfade(1000ms)` + Coil `crossfade(1000ms)`），再叠加常驻的 60fps 氛围背景。

## 决策

1. **全局统一，不分设备档位。** 所有优化对所有设备生效，不做运行时芯片能力探测。分档会引入"强设备误降级"的 bug 面，收益不值。
2. **动效分两级预算。** 导航动效（焦点移动、页面转场、菜单开合、列表滚动）极简化；氛围动效（Now Playing 背景、歌词滚动）保留观感但降成本。
3. **焦点视觉 = 描边 + 缩放，禁用 glow。** 缩放 1.05–1.08、时长 100–160ms；焦点态用 1.5dp 白描边表达，不再使用 `setShadowLayer` 模糊阴影。卡片用 1.5dp 白描边 + 1.05–1.08 缩放；紧凑传输按钮沿用填充+1.10–1.15 缩放，不描边。
4. **页面转场 200ms 快速淡入 + 8dp 位移**，替换默认 700ms 全屏 crossfade。
5. **Now Playing 内部模式切换（播放器 / 全屏歌词 / 屏保）250ms**，替换 450ms。
6. **封面切换硬切。** 过渡由背景渐变的 1.5s 调色动画承担；移除 Compose `Crossfade` 与 Coil `crossfade` 双层淡入。
7. **氛围背景 30fps。** 漂移周期 15–34 秒，30fps 与 60fps 肉眼无差别，全屏绘制成本减半。
8. **真机观测通道。** 电视开发者选项「GPU 呈现模式分析」柱状条 + App Dev 菜单帧时间悬浮窗；后者是阶段 1 的首个提交，用于后续所有改动的对照。
9. **验收方式。** Compose 编译器稳定性报告（本地可量化）+ 代码热点逐项消除 + 模拟器功能冒烟 + 真机 GPU 呈现条肉眼对比。真机 adb 量化指标推迟——当前家庭网关存在客户端隔离，adb 无法连接基线设备；脚本方案保留，网络环境恢复后补测。
10. **分三阶段交付**：阶段 1 低风险快赢 → 阶段 2 结构性改动 → 阶段 3 真机复核。每阶段改动保持可单独回退。

## 考虑过的替代方案

- **按设备分档降级**：实现复杂、体验不一致，放弃。
- **保留 glow 但缩小模糊半径**：`setShadowLayer` 的成本与半径非线性，且描边方案视觉已被 Netflix / Google TV 验证，直接去掉更彻底。
- **保留 700ms 转场**：与"渲染型卡顿"的诊断相悖——转场本身是卡顿感最强的区间。
- **氛围背景降为 15fps 或静态**：会明显损失 Now Playing 的"呼吸感"，30fps 是平衡点。
- **等待换路由器后再做量化测量**：会把整个优化拖成无限期，改为"静态 + 半自动验收，真机数据后补"。

## 后果

- 焦点态从"柔光晕"变成"清晰描边"，更接近 Netflix / Google TV 的克制风格，与 Apple Music 的柔光有差距——这是为弱 GPU 做的有意取舍。
- 转场变快后页面进出更利落，但少了"电影感"；若要恢复更长的动画，必须先在基线设备上用帧时间悬浮窗验证。
- 所有后续新增动效必须按「导航 100–160ms / 氛围 30fps」预算设计；超出预算的改动视为回归，需要先在本 ADR 里补证据。
- 强设备（Shield、新款 Fire TV）享受不到更丰富的动效；这是刻意换取行为一致与实现简单。
