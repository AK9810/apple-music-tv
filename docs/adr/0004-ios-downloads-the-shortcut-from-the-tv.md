# iOS 只从电视下载快捷指令，不再提供一键导入

**状态**: accepted（2026-11-14）

## 背景

#15 曾给 iOS 侧加过一条一键导入：页面按钮指向一个 https 上的签名副本，经
`shortcuts://import-shortcut?url=…` 直接打开「快捷指令」的导入预览。理由是 iOS 不接受
`http://` 的导入目标，而电视只提供明文 http。

2026-11-14 真机验证：iPhone 打开电视引导页，点「安装快捷指令」报 **导入失败**；同一份字节
从「从电视下载快捷指令」下载后，在「文件」里导入并运行成功。原因是 iOS 要求一键导入的 `url`
是**直达、不跳转**的文件，而 GitHub 的 release 下载先回 `302` 到签名存储地址。换成钉 commit 的
raw 直链可以绕开跳转，但那意味着为一个电视本来就能提供的文件，长期维护一条外部 https 分发链。

## 决策

**放弃一键导入，只保留「从电视下载快捷指令」这一条安装路径。**

- 页面的 iOS 页签以「从电视下载快捷指令」为主按钮，下载后在「文件」里导入；不再有
  「安装快捷指令」按钮，也不再展示 https 副本。
- `ShortcutDistribution`（`HTTPS_URL`、`importDeepLink`、`percentEncode`）及其单测一并删除；
  没有任何调用方的链接常量只会腐烂。
- 电视照旧在 `/send-token-to-tv.shortcut` 提供签名文件，这是唯一受支持的分发点。
- v1.7 release 上的资产保留为手动下载镜像，但 app 里没有任何链接指向它。

## 考虑过的替代方案

- **继续用 raw pinned-commit 直链**：能修掉 302，但需要联网访问第三方域名，且每次重新签名都要
  同步 commit SHA、单测与文档；换来的是"少点两下"，不值得。
- **自建 https 静态托管**：需要域名/证书/部署，个人项目的维护成本高于收益。
- **iCloud 链接**：官方支持一键导入，但由人工创建且无法随签名产物自动更新，放弃。

## 后果

- 用户装快捷指令从"一键"变成"下载 → 文件 → 添加"三步，多一次点击；换来的是不需要互联网、
  不依赖任何第三方主机，且路径已在真机验证。
- 一键导入的失败模式（`Import Failed`）不再存在，排障表相应减少一行。
- 之后若重新评估一键导入，入口在 ADR-0004 这一条：需要一个稳定、直达、随产物自动更新的 https 源。
