# 投影模式 —— AMTV 做了哪些不同

[English](PROJECTOR_MODE_NOTES.md) | **简体中文**

写给另一个 AI 的上下文：参考指南（PhairPlay 的 `docs/PROJECTOR_MODE.md`）描述的是*原始*投影模式。本文件列出 Apple Music TV（AMTV）实现与它**不同**的地方。如果你在移植，先读参考指南了解共享骨架，再应用这些差异 —— 正是这些部分让它在电视上、在歌词背后真正好看。

文件：`media/BeatAnalyzer.kt`（DSP）与 `ui/screens/NowPlayingScreen.kt`（`DynamicBackground` 的投影分支）。

---

## 1. 三个频段光球，而不是一个能量球

参考实现用单一的**低频起音能量**包络（一个 0..1 的数）驱动视觉效果。

AMTV 运行一个**三频段滤波器组**，每个频段画**一个光球**：

- **bass（低频）** = 单声道中置信号的低通（底鼓/贝斯）
- **treble（高频）** = 中置信号减去 4 kHz 低通（高频残余 —— 镲片/踩镲）
- **vocal（人声）** = 带通后的**中置**减去带通后的**侧信号**，即 `(L+R)/2` 与 `(L-R)/2` 之差。
  只有居中声像的内容能留下，因此主唱会显现，而宽声像的乐器会相互抵消。

这是一个滤波器组，**不是 FFT** —— 每采样三次乘法。在光球的尺度上，它与真正 FFT 的差异肉眼不可见，而且对孱弱的 Fire TV 音频线程来说足够便宜。

参考实现中的低频起音包络（`energy`）仍然存在，但它只驱动 **Dynamic（动态）** 背景的光球。投影模式改用三个频段电平。

## 2. 用「高于基线的隆起」归一化，而不是「电平与峰值之比」  ← 最重要的一条

参考实现（以及 AMTV 的第一版）用缓慢衰减的**峰值**归一化每个频段：`ratio = raw / peak`。在电视上这会**永远钉在最大值** —— 一个持续响亮的频段（四拍舞曲中的贝斯）就处在自己的峰值上，于是 `ratio ≈ 1` 恒定不变。光球看起来满格且死板。

AMTV 改用**缓慢的每频段基线**（约 1.5 秒 EMA）归一化，并测量*相对基线之上的抬升*：

```
base += 0.02 * (raw - base)            // 约 1.5 秒跟随，首个窗口时播种
excess = (raw / base - 1).coerceIn(0, EXCESS_MAX) / EXCESS_MAX
norm   = gate(excess)                   // 5% 噪声门
level += (norm - level) * (rising ? ATTACK : RELEASE)   // 上升快，下降慢
```

「处于自身平均水平」→ **0**，而不是 1。需要真实的抬升（一次底鼓、人声进入）才能点亮，因此光球会**随节拍脉动、在两拍之间回落**，而不是钉住。

真正重要的调参：
- `EXCESS_MAX = 1.1` —— 留出余量，让普通的重拍落在中段、只有最大的峰值才达到满值。调低（约 0.65）会让一切再次平顶在 1（那种「满格」观感）。
- `ATTACK = 0.42`、`RELEASE = 0.11` —— 不对称：重拍瞬间弹起，在*两拍之间*回落，让脉动可见。释放太慢 + 底鼓密集 = 永不回落 = 看起来满格。

## 3. 每个频段有自己的性格，三个才读得出是三个

每个光球用同样的半径/响应，看起来就只是一个东西在闪。AMTV 给每个频段各自的：

- **基础半径**：bass `0.26·min(w,h)`，vocal `0.21`，treble `0.16`（低频是那个又大又慢的）。
- **尺寸摆动**：高频相对自身尺寸打得最开（`1.05`），低频最小（`0.75`）。
- 每个光球跑**自己**的漂移动画 + 相位偏移，因此构图永不重复。

## 4. 静息时黯淡，重拍时爆闪（可读性）

歌词位于右半部分的灰色/白色区域。持续明亮的辉光会把它们冲淡。

- **光环透明度随节拍变化**：`0.24 + level*0.42` —— 静息时暗，只在重拍时亮。
  （参考实现让光环透明度恒定，以避免抬升黑色底。在真正的纯黑上配合 `BlendMode.Screen`，随节拍变化的光环没问题，而且是表现力的来源。）
- **核心**很小、偏白（`lerp(col, White, 0.6)` —— 真实辉光的最热点会去饱和），并且打得狠（`0.12 + level*0.62`）。面积小，所以能爆闪而不抬升黑色底。

净效果：静息与峰值之间差距大 = 有表现力，但*静息*电平足够安静，可以在上面读歌词。

## 5. 配色：三个不同的专辑强调色，并缓慢漂移

- 调色板从封面中挑出**三个分离度最大**的强调色（`spreadByHue`，或单色封面用 `spreadByValue` —— 见 #6）。
- 每个光球缓慢地*轻微*向相邻强调色插值（`0.10 + 0.18·t`），颜色随时间演化，但光球永不失去自己的身份。不是完整循环 —— 「有一点变化」。

## 6. 单色封面给出灰/白，而不是凭空造色

在饱和度提升**之前**检测黑白封面（`maxSat < 0.18`）。如果是单色：强制 `sat=0`，保留亮度分布，并按**明度**（`spreadByValue`）而不是色相分离光球 —— 当一切都是灰色时色相毫无意义，色相分离会让三个光球坍缩到同一个色阶。结果：三种灰/白色阶，忠于封面，而不是饱和度提升会幻觉出的假颜色。

## 7. 纯黑 + 轻微边缘淡出

- 投影模式用 `Color.Black` 填充，而不是 Dynamic 模式那种 `#050505` 的提亮面板。投影仪会把光投到墙上；接近黑色的提亮会变成可见的灰色矩形。
- 边缘暗角**很轻**（w/h 的 `0.10`）。参考实现/第一版用了很重的暗角，把黑色重新涂到辉光上，直接把它杀掉。光球很小且向内收，本来就到不了边缘 —— 淡出只是保证画面边框处没有发亮的矩形。
- 再加一个右侧渐变用于歌词可读性（是渐变，不是边缘淡出）。

## 8. 在 DSP 之上叠加 Compose 弹簧

DSP 本身已经做了平滑（attack/release）。Compose 层再加一个弹簧（`dampingRatio 0.6, StiffnessMediumLow`），让频段电平在约 33 次/秒的 DSP 更新之间滑移。过阻尼（0.95）会让它不再跟随节拍；欠阻尼会抖动。0.6 跟得住。

位置漂移保持**轻微**（`0.08·w`、`0.045·h`）—— 「动得少」是指光球不要在全屏游来游去；*脉动*（尺寸/亮度）才是能量所在。

光球锚点推到**右半边**（`anchorX = 0.52 / 0.62 / 0.72`），避免被左栏专辑封面挡住。

## 真机调优后的更新（也要读）

### 9. 人声需要「存在感」，而不只是隆起（§2 不够）

「高于基线的隆起」（§2）对低频/高频是对的 —— 它们读起来像*重拍*。但人声会持续保持一个音，没有节拍，因此它在音符进行中段的隆起约为 0，光球恰好在有人唱歌时变暗。所以**只有人声频段**额外计算一个绝对的**存在感** = `raw / decayingPeak`，并取 `norm = max(swell, presence·0.9)`。现在只要存在居中声像的人声，人声光球就是亮的，重拍隆起仍会在其上叠加。低频/高频保持纯隆起，避免变成常亮。每频段灵敏度存放在 `bandExcessMax` / `bandGate` / `BAND_PRESENCE_GATE`。

### 10. 强度是渲染的振幅，绝不是裁剪前的乘数

平静/正常/强烈/狂热 控件（`beatIntensity`，0.55…3.5）**不能**乘到 0..1 的 level 上再重新钳制到 1 —— 那会把一切钉在最大值，让 强烈 和 狂热 看起来一模一样，人声光球也永远满格。保持 level 在 0..1，把 `amp` 应用到**渲染**上：`r = baseR·(1 + lvl·ride·amp)`，`haloAlpha = 0.24 + lvl·0.42·amp`（带宽松的上限）。这样各档位才真正有区别。Dynamic 光球同理（`eAmp = energy·amp`）。

### 11. 颜色来自专辑 —— 绝不凭空发明色相

第一版通过**旋转色相**来合成「多样性」—— 结果在一张全橙色的封面上画出了蓝/绿光球。错。当封面没有 N 个色相分离的强调色时，用**它确实拥有**的强调色的更亮/更暗**色阶**填充剩余光球位置（`varyShade`，同色相，±明度/饱和度）。橙色专辑给出橙色系色阶；它永远不会制造出封面里没有的颜色。单色封面仍用 `spreadByValue`（§6）。

### 12. 歌词可读性

一个明亮光球漂到歌词栏下方会把暗淡的非活跃行冲淡。右侧的压暗渐变被加强（从 `0.30·w` 起，alpha 为 `0x9E`）。这比调暗光球更便宜也更好 —— 调暗会牺牲表现力的脉动。

### 13. 性能 / 内存（Fire TV 内存紧张）

Fire TV 4K Max 在负载下会频繁触发低内存杀手；应用是**在进入画中画（PiP）过渡时被 OOM 杀掉的**，不是代码崩溃。两个关键修复：
- **从小位图取调色板。** 每首歌都解码 1200² 的封面（`allowHardware(false)` → 约 5.7 MB 常驻内存）是浪费 —— Palette 反正会降采样。从 300px 源请求 `size(256)` 并复用 Coil 的共享加载器。每首歌内存减少约 20 倍，调色板完全一致。
- **在 PiP 中停掉动态封面解码器。** 动态封面是整整*第二个* ExoPlayer/视频解码器；在 PiP 过渡期间持有它正是 OOM 杀手回应的那个尖峰。用 `&& !state.isInPip` 门控，让它在进入 PiP 的路上释放。
